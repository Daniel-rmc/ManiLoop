## 一个可以继续收窄的候选

> 固定模型与动作接口后，当持续运动增益偏差和一次性执行失败产生相同的首次欠执行时，冻结 VLM 能否根据随后可识别的命令—实际位移历史选择原因相符的修正？

将“原因判断正确但下一步动作仍错误”作为诊断读数，是否升为主问题待讨论。首版可以只研究单轴、无接触小位移；一次性丢步比真实物体阻挡更容易控制，但结论也只能覆盖该诊断，不代表抓放能力或整个 LIBERO 成功率。

**必须先解决可识别性**：如果允许的传感历史完全相同，不能要求模型知道未来故障是否持续。需预先规定一个有界探测，使两种原因在后续历史中可区分，并证明它们需要不同修正。原因标签只供独立评分，不告诉策略，也不能藏在任务文字、文件名、episode ID 或恢复提示中。

**必须检查控制器混淆**：现有 `tcp_target_servo_v2` 会依据本体反馈追踪固定目标，可能自行消除动作增益偏差。若如此，不能把执行器补偿能力归功于 VLM。扰动实验应有独立协议与版本，不修改官方 LIBERO 控制器、动作缩放、初始化或评分来冒充原版 benchmark。

## 待讨论的最小判定表

| 项目 | 建议，尚未确定 |
|---|---|
| 模型与输入 | 冻结模型；同一 RGB／本体／命令与测量历史，不传入物体真值、接触真值或成功信号 |
| 同信息对照 | 完全相同且带时间戳的事件，比较普通表格与明确配对的反馈表达；匹配调用、图像与输出预算 |
| 时序消融 | 重复当前状态或打乱历史配对，只用于检验历史依赖；它改变可用信息，不能称同信息对照 |
| 确定性基线 | 固定重试，以及仅由相同命令—测量历史估计增益的有界修正器；不读取故障标签 |
| 主读数 | 预先定义的正确修正比例、实际执行残差；原因判断与动作一致性单独报告 |
| 反证 | 不能区分可识别的条件、修正不优于简单基线，或判断正确仍未产生对应动作；应保留负结果 |
| 统计边界 | 以独立 episode／初始化为分析单位；不把同一轨迹多个相关控制步当独立样本。样本数与最小有意义效应待预算和先导噪声估计后确定 |

API 错误、动作 schema 拒绝、控制超时和策略修正失败分开统计。历史原始轨迹尚未恢复，不能据旧文档重算成功率。网页 `/api/state` 含人类调试评分，不能整页／整包回流给策略。
