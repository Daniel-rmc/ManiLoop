# API 聊天测试

先用文字对话验证模型服务，再连接相机与机器人。这个页面只发送聊天文字，不启动任务、不执行动作，也不向模型提供仿真数据。

## 启动

完成根目录 README 的 Python 主环境安装后运行：

```bash
python -m maniloop chat --port 8769
```

打开 `http://127.0.0.1:8769/chat`。不需要安装可选 LIBERO 或 LeRobot 环境。运行新版仿真网页时，也可点击页首「API 聊天测试」，使用同一服务的 `/chat` 页面。两种入口均与机器人任务状态独立。

## 配置与聊天

1. 页面默认手动填写，也可选择导入／粘贴 `config.toml`，或读取本地配置／CC Switch。打开聊天页或仿真页不会自动发现或读取本地配置；选择本地配置后，可点击「发现本地配置」查找路径，也可手动指定。发现只列出路径；主动检查配置、获取模型列表或发送请求时读取所选配置，必要时读取配套认证。CC Switch 使用当前 Codex 供应商。
2. 填写 API Key。配置中已有 Key 时可留空；手工填入的 Key 优先。点击「读取并检查配置」，确认服务地址、模型和密钥状态。这一步不调用模型。
3. 输入模型 ID；留空会跟随配置，也可以获取服务商模型列表。供应商不提供列表接口时，直接输入模型 ID 即可。
4. 选择服务商支持的协议：`Responses` 与机器人当前接口一致；`Chat Completions` 用于兼容服务。Base URL 应为基础地址，不附加 `/responses` 或 `/chat/completions`。程序保留地址中的自定义路径。
5. 点击「验证内容」或输入自己的文字，再点击「发送消息」。支持多轮对话；只有完整回复会进入下一轮上下文。

默认单次请求超时 120 秒、输出上限 4096 token，可在「请求设置」中调整。每次发送只发出一个请求，可能计费；不会自动重试或偷偷切换协议。供应商的 token 统计可能包含其附加上下文，以返回的用量为准，页面不估算价格。

密钥、TOML 和聊天内容只保留在当前页面／请求内存，不存入浏览器持久存储或实验日志。刷新页面需要重新填写。切换配置、协议或模型会清空对话；本地配置在对话间变化时，服务端要求重新开始，避免将旧对话发往另一供应商。

## 读懂结果

- **完整回复**：HTTP 请求通过，响应符合所选协议的完成条件，并且有助手正文。可以继续聊天。
- **收到响应，但回复不完整或格式异常**：服务返回了内容，但不能认定完整成功。页面保留部分文字，并展开响应状态、错误码／信息、未完成原因和输出条目状态。
- **HTTP 错误**：查看状态码和服务商的脱敏错误信息。认证失败、限流、模型无权限、路径错误等不能混为同一个问题。
- **超时或连接失败**：不能确认供应商是否已处理或计费。不会自动重试；调整配置后再手动发送。

聊天成功仅证明文字通信。图像输入、严格结构化动作及机器人任务成功必须分别验证。机器人执行端继续拒绝真实错误、不完整动作、过期观测及不合法动作。

## 实现与验证依据

使用同一 OpenAI SDK 与凭据解析器，聊天适配器独立于动作策略；通过 SDK 的原始响应接口查看所选字段，不返回完整响应包或认证头。参考 [Responses 创建接口](https://developers.openai.com/api/reference/python/resources/responses/methods/create) 与 [Chat Completions 创建接口](https://developers.openai.com/api/reference/python/resources/chat/subresources/completions/methods/create)。

离线验证覆盖实际 SDK 请求、两种协议、多轮上下文、配置切换、部分回复、拒答、401／429／500、超时、密钥脱敏和本地页面访问限制。真实服务结果与兼容性修复维护在 [工作记录](worknotes/worknote.md)。
