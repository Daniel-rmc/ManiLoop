# 项目工作记录规范

本目录保存 ManiLoop 的长期工程记录。`worknote.md` 是统一入口，用于让维护者理解当前进展、关键决策和验证依据，不替代安装文档或 Git 提交历史。

## 何时更新

- 开始一项重要功能：记录目标、范围、里程碑和当前限制。
- 完成一个可验证的里程碑：当次更新，不等整个项目结束。
- 遇到影响设计或交付的障碍：记录问题、证据、处理方法和剩余风险。
- 结束或交接：更新当前状态、复现入口和下一步。

## 每条记录应包含

日期、里程碑名称、状态（进行中／完成／受阻）、目标、实际变化、验证命令及结果、困难与处理、可复用经验、未完成事项。链接使用仓库相对路径；涉及第三方代码时记录仓库和固定版本。

较新的记录放在前面。保留旧记录；若早先结论有误，追加更正并说明原因。开头的状态概览随进度维护。区分「接口模拟通过」「真实环境运行通过」「真实模型任务成功」，不把三者混写。

不要记录密钥、认证文件内容、个人路径、完整终端输出或大体积实验数据。实验文件保存在忽略的输出目录，工作记录只保留命令、摘要与必要证据。没有实际运行的检查明确写「未验证」。使用简明中文，解释为什么做，而不只是罗列文件名。

## 模板

```markdown
### YYYY-MM-DD · M编号 · 里程碑名称（状态）
- 目标：
- 变化：
- 验证：命令、环境、实际结果。
- 难点与处理：
- 经验／决策：
- 后续：
```
