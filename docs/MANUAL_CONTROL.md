# 手动六维位姿控制

手动面板支持 XYZ 平移、Rx/Ry/Rz 旋转、夹爪开合及自定义六维增量。
不需要模型或 API Key。该面板改变的是 TCP 目标，不是直接写入仿真关节状态。

## 如何转动夹爪

1. 选择已经接通的环境，先停止模型并等待当前动作结束。
2. 在“手动参考坐标轴”选择固定轴或末端自身轴。
3. 设置“角度步长”，点击 ±Rx、±Ry、±Rz。

固定轴随后端解释：内置 MuJoCo 为其声明的 base，LIBERO / robosuite / RoboCasa 为 world。
末端自身轴由服务端在收到命令时读取当前 TCP 姿态计算，不依赖浏览器缓存的姿态。
例如末端自身轴的 ±Rz 是绕夹爪当前 Z 轴转动；世界 Rz 不一定是相同的转动。
正方向使用右手规则。界面角度为度，传给底层的是弧度。

纯旋转发送 `delta_position=[0,0,0]`。在目标跟踪模式下，控制器尝试保持当前
TCP 位置，同时达到新的姿态；它不是将机器人刚性锁死在空间里。

## 两种不同的“转最后一个关节”

**TCP 姿态控制：** 指定末端朝向，由多个机械臂关节协同实现。
**J7 单关节控制：** 指定第七关节目标，并另行定义其余关节如何保持。

当前外部后端的 OSC_POSE 模式使用前者。其七维动作是“3 平移 + 3 旋转 + 1 夹爪”，
不是七个机械臂关节目标。内置后端已有命名 joint_position 接口，但外部后端尚未
适配单关节点动。这里不偷偷切换控制器，也不把 TCP 旋转标成 J7 独立旋转。
RoboCasa 的七维手臂子接口最终会组装为完整的十二维上游输入；底座和躯干仍保持。

## 六维增量与控制语义

展开“自定义六维增量”，可同时设置 ΔX/ΔY/ΔZ（毫米）和 Rx/Ry/Rz（度）。
旋转的三项是**单次旋转向量的分量**，不是绝对欧拉角，也不是三个依次执行的旋转。
固定轴：`R_target = Exp(delta_rotation) @ R_current`。
末端轴：`R_target = R_current @ Exp(delta_rotation_tool)`。
服务端以 `delta_rotation_fixed = R_current @ delta_rotation_tool` 完成等价转换，
同一条动作的参考姿态只采一次。工具轴平移也按同一姿态转换。

所有数值、向量范数和坐标系都会校验；越界明确拒绝，不静默裁剪。
夹爪保持原有接口；平移和旋转不会隐式改变夹爪命令。
动作期间按钮禁用，可停止剩余动作；不会触发任何模型请求。

## 到达不等于接受，位置保持也不是物理约束锁定

保留当前控制器与增益。模型目标跟踪仍是 20 控制步（1 秒）。
手动面板单独提供“手动目标跟踪时限”，默认 3 秒，可设为 0.05–10 秒，
只延长同一个固定目标的执行预算，不重复累加角度；不会修改模型的动作预算。
原生单步模式仍只执行一次 20 Hz 命令，不保证旋转了界面所写的全部角度。
面板显示实际姿态误差（度）、TCP 位置误差（毫米）与 reached / timed_out。

在部分姿态下，短执行预算可能不足以收敛；旋转过程中也可能出现平移误差。
靠近物体时优先使用较小角度，并检查反馈和相机。允许增加手动跟踪时限不代表
任意目标都可达；关节限位、接触和控制器动态仍然有效。不要把 reached 当作任务成功。

## 版本与验证

网页根据后端 `manual_control.protocol=tcp_jog_fixed_tool_v1` 启用新控件。
旧 Python 服务即使重新读取了新 HTML，也不会静默把工具轴命令当成世界轴命令。
需使用加载新代码的服务；重载网页本身不能更新旧 Python 进程。

回归检查（需要分别安装对应的可选后端）：

```bash
MANILOOP_TEST_ROBOSUITE=1 MANILOOP_TEST_ROBOCASA=1 python -m pytest \
  tests/test_manual_control.py tests/test_manual_control_integration.py -q
```

需要检查 LIBERO 时再启用 `MANILOOP_TEST_LIBERO=1`，并按 LIBERO 文档配置其独立环境。
[robosuite 官方控制器说明](https://robosuite.ai/docs/modules/controllers.html)区分了
OSC_POSE 与 JOINT_POSITION；本功能没有把两种输入空间混为一谈。
